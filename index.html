Architecture

Five stages, each with one job. Everything runs on the Google Cloud free tier plus credits.

  1. ProducerPython script publishes one JSON order event per second
  2. Pub/SubTopic holds events and retries delivery until acknowledged
  3. Cloud FunctionValidates each event and writes it with an insert ID
  4. BigQueryStores every event in the order_events table
  5. Dashboard APICached SQL aggregates served to this page

Design decisions

The choices an interviewer is likely to ask about.

At-least-once delivery

Pub/Sub can deliver a message twice. Each row is inserted with order_id as its insert ID so BigQuery drops duplicate retries.

Bad records do not block the stream

Events with a missing ID or a non-positive amount are logged and skipped. A failed insert raises an error so Pub/Sub retries it.

Cached dashboard API

One aggregate query runs at most every 20 seconds, however many people open the page. This keeps BigQuery inside its free allowance.

Cost guardrails

Maximum instances are capped on both functions, a budget alert is set, and the producer and functions are stopped when not in use.

Challenges and what I learned

Every one of these was diagnosed from logs and fixed with a least-privilege IAM role.

Build failed on deploy

Cause: the default compute service account lacked the Cloud Build role.

Fix: granted roles/cloudbuild.builds.builder.

Trigger validation error

Cause: Eventarc could not validate the Pub/Sub trigger without serviceusage.services.use.

Fix: granted roles/serviceusage.serviceUsageConsumer and the Eventarc receiver role.

Messages sent, no rows

Cause: the push subscription authenticates with an OIDC token, and Cloud Run rejected it with "request was not authenticated".

Fix: granted roles/run.invoker on the function's service to the subscription's service account.

Broke again after redeploy

Cause: deleting a function deletes its Cloud Run service and the IAM binding on it, so the new service started without permission.

Lesson: this is why infrastructure belongs in Terraform, where bindings are declared once and reapplied.
